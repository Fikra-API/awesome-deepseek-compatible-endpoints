Anyone can add an endpoint: open a PR against this README with a table row for one provider. No vendor holds a green light: each listing is a shared, mechanical record.

## Rules for a listing

- One row per provider, alphabetical by provider name after the first-block rule.
- **DeepSeek-first ordering**: any endpoint that serves DeepSeek-family models lists those models first, then companions (GLM, Kimi, StepFun, Qwen, other open weights), then house/private models.
- Quote only published prices. Link the pricing page or model card; no proxies to closed portals.
- Note the endpoint's host + path and whether it is ModelArk-style (Provider-standard `/v1/chat/completions`).
- For per-region deployment edges (like Nairobi latency), note it in the row once.
- Update Verified only when the link opens and the table's rates parse.
- Ads, referral codes, and bounty pitches in PR bodies: yes, briefly. Behind the row: no.
- Dead, unrenewed, or redirect-only restaurant rows get struck out (~~name~~) before removal notice.

## How to add yours

1. `Fork` this repo.
2. In README.md, add one row to **Endpoints** in alphabetical position; the **DeepSeek-first ordering** rule applies inside the "DeepSeek models" and "Also on this endpoint" columns.
3. PR title: `add <provider>`. Include the pricing-page link used for Verified.
4. A maintainer merges within a day, or comments what is missing (a source link, a rate, an endpoint path).
